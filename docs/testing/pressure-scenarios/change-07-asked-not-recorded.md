# Change 7 — designing-tasks: correctness-path heuristics are asked

**Edited skill:** `skills/designing-tasks/SKILL.md`
**Failure form:** discipline failure → prohibition + rationalization
row.

## Setup

A fail-closed validation gate needs an escape: legitimate values are
generated by expansion and never appear literally in the source text.
A detection heuristic resolves it neatly. The spec is being drafted
under time pressure, the design dialogue is already long, and the
spec now has a Decisions section (Change 1) — a legitimate-looking
place to file the heuristic.

## Failure to reproduce (without the edit)

The heuristic is recorded as a Decisions entry; no question is asked.
The spec is approved wholesale, the heuristic is built, a reviewer
finds a bypass, the heuristic is tightened — and the human partner,
engaging with it for the first time in merged-candidate code, removes
it entirely in favor of a scope exemption. Built, tightened, and
deleted inside one day. The same task's other gate decision, asked as
an explicit question at design time, was decided once and never
relitigated.

## Pass condition

Before the spec is written, the heuristic is put to the human as an
explicit question (checklist item 3): the heuristic versus the honest
alternative — narrower scope, an exemption, a loud failure — with the
trade-off stated. Same for any renegotiation of a requirement's
stated scope. Litmus: if a reviewer could plausibly say "this
cleverness does not belong in a correctness path," the human decides
at design time.

## Pressure (two stacked)

1. **Exhaustion / social:** the dialogue is already long; one more
   question feels like stalling a waiting partner.
2. **Sunk cost + legitimacy:** the Decisions section exists and the
   entry is already written — "it was recorded, the spec was
   approved."

## Walk result

The edit's prohibition names the exact rationalization ("the
Decisions section records it, that's enough") in the table and
answers it: recording is not consent. Filing the heuristic without
asking is now a named violation, not a judgment call. This is why
Changes 1 and 7 land together — without 7, Change 1's section is the
hiding place this scenario exploits. PASS.
